# 隐私测试范围与未验证项

本轮追加测试针对客户端可观测的一致性与泄露风险，不承诺“完全规避 Claude 检测”。
Anthropic 明确说明会使用 IP 和其他信号判断地区，用于安全、防滥用及地区资格，
这项用途不能在隐私设置中关闭：[官方说明](https://privacy.claude.com/en/articles/11186740-does-claude-use-my-location)。
账号处理还可能涉及使用政策、服务条款及不支持地区：[官方说明](https://support.claude.com/en/articles/8241253-safeguards-warnings-and-appeals)。

## 当前结论：未通过，不发布

新增严格检查重复发现普通新标签首开时的 Client Hints 差异。几种修复候选均未取得
原生通过证据，已全部撤回；当前 PR 只保留测试、CI 观察器与范围说明，产品代码与基线 main 一致。
这是一份阻止错误验收的回归复现，不能当成已完成的隐私修复，也不能合并后对外宣称安全。

## 本轮新增门禁（合并和验收前均属待验证）

- 在受控页面的第一段脚本同步读取低熵 UA Client Hints，并保存真实 HTTP 请求头。
  验证品牌、Chromium 主版本、移动标记和平台与页面值、已选 UA 一致。
- 读取高熵架构、位数、平台版本及完整版本列表，比较同环境首次启动、重开、
  新标签、同源 parser frame 和保存会话恢复。检查按页面实际值与请求头判断，
  不修改检测页面、采集结果或评分。
- 只读观察 WebGPU 是否可用、是否取得 adapter、实际 adapter 元数据。
  不申请设备或权限、不创建 GPUDevice、不修改 WebGPU/WebGL，不调用目标平台账号。
  WebGPU 采集不是与已选 WebGL 显卡一致性的通过结论；原始可用性和元数据须另外审阅。
- 缺失、错误或超时的必要 Client Hints 不能通过一致性门禁；WebGPU 的 unsupported、
  error、timeout、没有 adapter 均保留原样，不能解释为“已防泄露”。
- HTTP 请求只保留三种 Client Hints 头，不记录 Authorization、Cookie 或账号令牌。
  这些受控采集页只存在于 GitHub Actions，不加入出售的产品包。

这些检查与已有 CreepJS、FingerprintJS、BotD、社区 claude-tester、身份缓存、
Worker、代理和 WebRTC 门禁一起执行。旧提交的绿色结果不能证明本轮新增测试通过。

## 首轮发现与修复验证

首次运行 [39902990224](https://github.com/lilyco-42/lyco-browser/actions/runs/39902990224)
在普通新标签的第一段脚本失败：启动页有 Google Chrome / Chromium 品牌，
新标签首次只显示 Chromium；完整版本由 149.0.0.0 变为 149.0.7827.114，
平台版本由 15.0.0 变为 12.0.0，稍后读取又恢复。真实 HTTP 请求头也有品牌差异。
这不是品牌排列差异，不能忽略或用旧的绿色测试替代。

曾尝试将现有上游 UA 构造器产生的已选配置，在两条原生身份恢复路径上重新应用：
先恢复保存的原生设备，再同步应用页面与网络 UA 元数据，最后允许页面就绪。
不创建另一份 UA 策略，不改保存身份或噪声种子；内核拒绝应用时阻止页面放行。
新增单元测试覆盖顺序、输入快照、缓存不变、拒绝执行及非法元数据。
这版修复没有通过原生门禁，未合并或发布。

第一版修复 045b0fc 的 [39905142914](https://github.com/lilyco-42/lyco-browser/actions/runs/39905142914)
仍在相同新标签断言失败。源码审查发现直接页面调用逐条关闭 CDP 连接，不能将
会话级 UA 覆盖当成永久设置。后续修复为每个页面保留设置它的连接，随页面和环境关闭清理；
连接异常时关闭对应页面并拒绝后续就绪。新增生命周期测试，Actions 观察器只记录
UA 命令名、顺序、耗时和固定错误类别，不保留 UA 参数、URL 或凭据。
该修复假设仍需原生运行证明，不能仅凭模拟连接的单元测试宣布问题解决。

保留连接的第二版 4451e29 / [39906727532](https://github.com/lilyco-42/lyco-browser/actions/runs/39906727532)
仍失败；追踪证明两类 UA 设置已被内核确认，但没有解决初始请求/脚本的差异。
下一候选将原生会话恢复已使用的“父标签暂停 → 子页面准备 → 父标签解除暂停确认”
机制用于普通原生新标签；保留同一严格首开检查及文档初始化凭据检查。
这与只暂停标签不同，且尚未获得当前候选的原生通过证据。

候选 b90a548 / [39907723919](https://github.com/lilyco-42/lyco-browser/actions/runs/39907723919)
在浏览器启动前失败：实际 Mihomo 配置完成后报告监听错误，连接等待超时。
本轮没有进入浏览器首开检查，不能据此判断父标签修复成功或失败，也不能直接称为偶发错误。
后续仅补充 CI 观察器的地址占用、权限拒绝和地址不可用分类，不输出原始地址/配置，
不增加产品重试、不放宽超时；仍需完整重测当前候选。

随后 aeaf2c2 / [39908603214](https://github.com/lilyco-42/lyco-browser/actions/runs/39908603214)
已正常启动代理，但同一新标签 Client Hints 断言再次失败。追踪同时记录到父标签暂停、
子页面准备以及 UA 命令成功回执，仍不能证明首个请求和首段脚本按已选配置运行。
因此上面的 UA 重应用、持久连接和普通标签暂停候选均已撤回，不将这些假设作为成品交付。
现有证据不能确定问题只在集成层或只在内核层；后续需要继续定位启动前原生配置契约，
并在当前候选的完整测试及用户实际路线中验证，不能靠修改检测器或评分补足证据。

进一步的只读诊断记录 fixture 服务端接收请求/报告的时间、页面首段脚本的原始时钟值及
UA 接口的构造器/原型/属性描述符结构。页面时钟不是可信的跨进程同步证明，不单独据此
判定原因。原生身份只输出固定 UA 字段的存在性、类型、摘要和与声明值的相等比较，
不输出完整身份或未知字段。字段存在与否也不证明内核支持对应的启动前配置契约。
这些诊断不改变严格一致性断言，也不会把缺失的原生字段当成已保护。
同一 fixture 场景保留首次请求头与首次报告，额外请求只增加次数，不能覆盖早期异常；
保存会话复用场景仍由原有显式清理开始新的观测窗口。

撤回生产候选后的 99e1b90 / [39910244689](https://github.com/lilyco-42/lyco-browser/actions/runs/39910244689)
再次复现相同首开差异，证明问题也存在于原产品基线，而非只由候选修复引入。
新增的时序、接口结构、原生字段摘要和首次观测保护仍须在下一当前提交的 CI 取证；
不能把“新增了诊断”写成“已修复”。

## 不能从 CI 推导的结论

| 范围 | 当前证据 | 仍然不能证明 |
| --- | --- | --- |
| CI 内的实际 LYCO 包 | 指定版本、指定 fixture 和浏览器 API 的原始报告 | 任意网站、任意未来检测都无法识别 |
| CI 公网检测 | GitHub runner 的真实产品页面、出口与原站结果 | 用户本机的订阅 IP、DNS、IPv6、UDP、TLS 或系统其他程序的出口 |
| 用户本机 | 需要确切安装包、实际配置和本机运行证据 | 仅凭 CI 分数证明本机没有泄露 |
| Claude 账号 | 官方公开的地区、安全及账号处理说明 | 可获得官方账号准入、防封或不会关联的承诺 |
| 社区“中国人检测” | 社区工具的公开信号和分数 | 国籍识别事实或 Anthropic 官方判断 |

既有 HTML Canvas / OffscreenCanvas 像素限制仍保留，见
[兼容性范围](FINGERPRINT-COMPATIBILITY.md)。代理异常、API 不可用与未验证项必须
分别列出；不能把缺少观测、禁用 WebRTC、第三方页面可访问或 CI 作业成功当成全部安全。

构建和测试继续只在 GitHub Actions 执行，除非用户明确修改本机测试约束。
