# 每个受管环境选择官网节点

为紫鸟 / 站斧对标补齐逐环境网络控制。旧受管环境保留默认订阅线路；登录有效官网订阅后，在「账户与代理」加载官网线路，为新环境选择固定节点，也可以在环境线路绑定列表中更换已有环境的节点。更换会先关闭该环境，下次启动应用新选择，其他环境保持各自连接。

固定的是所选节点，不保证节点拥有独享或互不相同的公网 IP。官网账号、月卡/季卡/120天套餐/年卡授权仍沿用规范 `proxy_1m` 服务码。无真实付款或客户线路验证，不改变已经部署的套餐 P0。

## 实现与数据兼容

`workspace-routes.js` 复用 Mihomo 与现有安全配置生成器，为指定节点的环境分配独立进程、回环端口和私有配置目录；默认线路继续复用原有主连接。该改动不安装系统代理，不开放外部控制接口或局域网监听。单个环境停止或线路意外退出时清理对应连接；全局断开、退出、应用关闭及权益撤销时清理受管连接。

主进程重新核对账号、权益、父连接代次及所选节点。节点被移除、账号或连接变化、线路绑定在启动途中被修改，均拒绝继续，不默默切到默认节点。刷新节点目录保留已有选择；账号切换清除界面目录。目录返回不含节点端点、用户名、密码或订阅正文，只提供有界名称与不透明 ID。

明确选择节点后，`lyco-workspaces.json` 升为版本 2；继续接受原有版本 1。旧读取器会拒绝版本 2，避免降级时忽略固定节点；不清空旧环境或浏览数据。原来共享代理记录的克隆环境在启动前拆成独立记录，防止并发启动互相覆盖端口。此绑定文件不包含网站 JWT 或节点凭据。临时 Mihomo 配置仍需要节点凭据，按用户私有目录与文件权限保存，停止时清理，不进入验收工件。

## 实际验证

全部构建和运行发生在真实 GitHub Actions。Billing 为隔离夹具，上游、源站和保留地址的出口查询响应为明确的 CI 设施；路由结论依据源站实际接收连接的 TCP 端口归属，不使用网页自报线路或可伪造的请求头。

- `2712397` [40639563179](https://github.com/lilyco-42/lyco-browser/actions/runs/40639563179) 首次通过真实 Mihomo 两路认证上游、停止重开、A 上游失效不走 B/直连、B 继续工作、独立直连对照、撤销权益和配置清理。
- `7d19d6c` [40641905733](https://github.com/lilyco-42/lyco-browser/actions/runs/40641905733) 的 Windows/macOS/Linux 三个核心路由任务通过单元门禁及相同真实 Mihomo 用例。Linux 实际打包应用完整 14 项通过，其中新功能包含实际可见菜单选择 A/B、两个原生浏览环境同时运行、同源 Cookie/localStorage 隔离、A 重开仍走 A、A 上游失效后不访问源站且 B 继续工作，以及界面换线只停 A、A 改走 B 后仍保留自己的存储。原有字体、RTC、失效代理和直连对照断言继续执行。
- 同轮 macOS 原生任务在原有硬件/显卡配置拒绝处失败，未到达新线路用例；整个 Unix 工作流因此失败。不能将 macOS 核心路由成功扩大为原生浏览器成功。
- 同源码 Windows [40641909641](https://github.com/lilyco-42/lyco-browser/actions/runs/40641909641) 的原生预检完成新功能四项检查和五个实际网页观察，随后在原有受管浏览器用例未收到预期代理请求，最后 CPU 匹配回执为 false。便携/安装成品阶段未执行，仍不可发行。

早期 `40640042020` 原生驱动的出口查询夹具不完整，未验证新网页流量；`40640902589` 的 Linux 已通过并行/隔离/重开/失效负向，最后被含两个按钮的定位器拦住。最终用可见下拉菜单与精确的「停止并更换线路」按钮完成该步骤，保留了原始失败报告，没有放宽产品启动或隐私门禁。

## 剩余范围

上述证明覆盖测试的 HTTP 上游和桌面场景，不是客户公网出口、所有节点协议/链式订阅、完整 DNS/IPv6/RTC 或防关联效果的通用证明。当前固定选择重写 `PROXY` 组；依赖该组的 `dialer-proxy` 链仍需单独适配和验收，未声明全量链式订阅兼容。Android/iOS 的逐环境官方节点选择、团队授权与同步等对标项仍需继续完成。浏览器原生硬件/显卡兼容、iOS 路由、签名与商店等五平台发行门禁保持。
