# 桌面中文界面字体

Linux `f3f08b3` 功能测试通过后的原始截图出现中文缺字方框，因此该包仅保留为诊断候选，不能视为可交付。界面此前依赖操作系统字体，最小 Linux 安装不一定提供中文字符。

桌面构建现在使用 Google Fonts 固定提交中的完整 Noto Sans SC 可变字体。`resources/ui-font/manifest.json` 记录不可变来源、长度及 SHA-256；原始 SIL Open Font License 全文同目录保留。构建中的 `scripts/ui-font.mjs` 校验字体、中文字形映射及许可证，再将原件复制到应用的 `lyco/ui-font`。不修改字体内容、不安装系统字体，不向用户网页注入该字体，也不改变浏览环境的字体隐私设置。

字体只从固定官方 HTTPS 来源获取，不跟随重定向。下载损坏、长度/摘要不符、字形缺失或许可证不符会阻止打包。应用运行时从随包文件加载，无需网络。开发源树不提交 17 MB 的字体二进制；在 Actions 执行现有 `scripts/apply.js` 时会准备并校验它。

真实打包应用的验收检查字体原件及许可证摘要、实际 FontFace 加载、中文标题使用的字体，以及六个中文字形非空且各不相同，并保留原始界面截图。它只测工作台界面，不替代网页字体隔离或设备指纹验收；原有硬件、网络和独立环境断言继续执行。

`fa40538` 的真实 Actions [40633763490](https://github.com/lilyco-42/lyco-browser/actions/runs/40633763490) 中，Linux x64 完整 13 项验收通过，包含新增随包字体/许可证摘要、实际字体加载、中文标题与六个不同字形检查。人工复核原始工作台和 120 天账户截图也确认中文可读。归档 SHA-256 为 `7d61d019e9faf56e18f3ad137de838605b19b6cabd8b302e5c43260f9f75bb7c`，候选仅保留在未发布草稿 `ci-fa40538efb57`；该结果替代旧包的中文显示缺陷记录，不扩大为五平台发行证明。

同轮 macOS 字体及三周期显示检查通过，随后仍因内核未接受硬件/显卡配置而失败。Windows 首次 [40633767812](https://github.com/lilyco-42/lyco-browser/actions/runs/40633767812) 被许可证 CRLF 转换的摘要校验拦截；`bd6b19f` 用 `.gitattributes` 保留原始 LF 后，[40634181774](https://github.com/lilyco-42/lyco-browser/actions/runs/40634181774) 实际预检 52 项成功，便携成品字体及三周期显示也成功，原始 120 天截图中文可读。但便携成品在 B 首次启动时没有返回浏览器观察，最后一次原生写入回执的 CPU 匹配为 false（内存匹配为 true），完整运行失败，安装版验收未执行。便携报告在失败前记录 29 项通过。这次字体修复不代表内核配置冲突已解决；保留原有硬件、代理与隔离断言。原始 Actions Artifact 已保留；额外草稿证据保存步骤被 GitHub integration HTTP403 拒绝，没有据此创建新 Windows 可交付候选。
