# Original website keys across real Android installs

This is the next preservation gate before changing the product's browser
engine. It uses the actual retained old APK and an existing unchanged
owner-signed candidate. It neither rebuilds nor resigns either binary.

The [WebCrypto specification](https://www.w3.org/TR/webcrypto/) requires
`exportKey` to reject a non-extractable key. Structured cloning within a
browser does not establish cross-engine storage compatibility. Existing
Gecko wrappers and browsers do not prove migration of these actual WebView
profiles. The original WebView root, metadata, runtime and default installer
remain unchanged while the missing key-preservation evidence is gathered.

The separate `android-legacy-keys.yml` workflow prepares an Actions-only
fixture copy, pinned to eight original input hashes. It retains the original
fourteen paid assertions, fifteen native UI flows, three website data types,
search/edit/restart, actual old APK upgrade/downgrade/return, routing negatives,
account boundaries, default TLS rejection and revocation. Original assertion
files and `RESULT.json` are unchanged. Private CA/database copies are cleaned.

Only the derivative owned origin changes to secure loopback and receives an
additional website script. Its server authorizes exactly two seed pages: A in
the actual old APK before upgrade, B on the first B visit. Every later page
must read the original key; missing keys never generate replacements. All
eight real origin reports must retain `extractable=false`, actual export
rejection, successful original-ciphertext decryption and the same ciphertext
digest for that environment. A/B digests must differ. Key material, IVs,
ciphertext and private databases never appear in the evidence. Only test-owned
keys are used; no customer profile or secret is accessed.

The derivative historical downloader pins this separate workflow's exact path
for its preparatory job. Historical source/workflow/file hashes, read-only
device job permissions, owner certificate and actual artifact gates remain.
Original and generated fixture sources, exact transformations, hashes and
added scripts are retained before device execution. No preparation, parsing,
build or runtime command is executed locally.

This gate is prepared, not yet validated. It does not establish Gecko adoption,
generic WebView-to-Gecko key migration, ARM64, power-loss durability, product
RTC, real payments, iOS, signing/distribution or five-platform readiness. A
successful old/current retention result must not replace those requirements.
